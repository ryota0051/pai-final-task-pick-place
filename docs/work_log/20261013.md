### 置き場所のランダム化（実験12）の学習・評価
- 2 クラスの検出器（物体・置き場所）を学習。スコアが全体に低く、しきい値 0.5 では物体を 14% しか検出できなかった
  - 当初は評価用データで 0.2 を選んだが、ユーザーの指摘（テストデータでしきい値を決めてよいか）を受け、学習時の検証用 120 枚で決め直して 0.15 にした。
    評価用 300 枚で物体 298 枚（誤差 0.31mm）、置き場所 293 枚（0.47mm）を検出
- 真値での評価: 置き場所ランダム 29/30。比較（ユーザー提案）: 置き場所を観測しない元のモデルは置き場所ランダムで 1/30、新モデルは置き場所固定でも 30/30
- 検出器で動かすと 26/30・24/30 に低下。原因は、掴むとグリッパが物体を隠し、推定値がずれたまま保持されること（真値との差 100mm）
  → 改良 A': グリッパが閉じている間は物体の観測を閉じる直前の値で固定（学習データも同じ規則）。検出ノードは直近 3 回の中央値。
  検出器 28/30、見た目ランダム化 28/30、真値 29/30
  - 方式はユーザーと相談して決定（開始時の値で固定する案 A ではなく、開いている間は更新し続ける A'）
- 左前で掴み損ねる原因の調査（ユーザーの「2 → 3」の指示）:
  - スクリプトデモ: 関節（肘・手首）が指令より 4〜6° 足りず手先が 6〜10mm 高く止まる追従誤差で、開いた指が物体の上面に当たって押し出す。
    寸法は正しい（自作 FK と URDF の TF が 0.00mm で一致、ユーザーの確認依頼）。下降後に待ってから閉じる `grasp_settle` は効かなかった
  - 方策: 元のモデルは同じ配置で 4/4 成功、A' は 0/4。A' は横移動の途中から斜めに下ろす → 方策の精度の問題と判断し、制御の変更（①）は見送り（ユーザー判断）
  - デモを倍（701 本）にした x2 を学習・評価: 28/28/27/30、置き場所固定 27/30 で改善せず。失敗する場所が移っただけ（x2 は狙いが約 7.5mm ずれる）
  - temporal ensembling の係数（0.01 / 0.1 / 無効）でも 28〜29/30 で改善せず
- 最終モデルは A'（339 本、係数 0.01）。置き場所固定で成功率がわずかに下がる可能性（100% → 93%）は、レポートに正直に書く（ユーザー判断 C）
- 評価器の退避の修正（ユーザー指摘）: 物体を置いた後の退避で、置いた物体をなぎ倒して動画の見栄えが悪い → まず真上に上げてから退避（`observe.lift_time`）。
  82 試行で次の試行開始時の物体は直立していたので、成否には影響しない
