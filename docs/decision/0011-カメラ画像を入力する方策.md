# 0011 カメラ画像を入力する方策（A 案: 関節角 + 画像）

- ステータス: 実装・評価済み（2026-10-16）。説明資料に入れるかは未定
- 日付: 2026-10-16

## コンテキスト
これまでの方策（ACT）の入力は、関節角と数値の物体位置・置き場所だった。
物体位置は真値（ADR 0005）か、カメラ画像からの検出器（赤色検出・RT-DETRv2, ADR 0008 / 0009）で得て、方策には画像を入れていない。
課題の発展として、方策に画像を直接入力できないかとユーザーから相談があった。

- 俯瞰カメラ（`/task/camera/image`、320×240、10Hz、真下向き）はすでにあり、検出器が使っている
- 同梱の LeRobot の ACT は `observation.images.*` を定義すると、ImageNet 学習済みの ResNet18 で画像を読む（モデルのコードは変えなくてよい）
- これまでの rosbag には画像が入っていない

## 検討
- **A 案: 関節角 + 画像（物体位置・置き場所なし）**: 物体と置き場所の位置を方策が画像から読む end-to-end の形。
  検出器 → 数値の物体位置という今の構成と比べやすい
- B 案: 関節角 + 画像 + 物体位置・置き場所: 画像を補助として足す。安定しやすいが、何が効いたのかを説明しにくい

## 決定
A 案を採る（2026-10-16 ユーザー決定）。

- データ: 最終モデル A' と同じ条件（置き場所ランダム、固定開始 200 ＋ 開始姿勢ばらつき 200、seed 1200 / 1201）で、
  カメラ画像を加えて収録し直す（`recorder_image.yaml`、録画先 `~/dataset/rosbags/pick_place_image`）
- 変換: 変換設定に `observation.images: [<カメラ名>]` と `topics.<カメラ名>` を追加し、`environment_state` は空にできるようにした。
  画像は 20fps の各フレームで直前の画像を使う（カメラは 10Hz なので 2 フレームずつ同じ画像）。
  全エピソードの画像をメモリに載せると数 GB になるため、1 回目は時刻だけを集め、書き込み時にエピソードごとに読み直す
- 学習: A' と同じ 80k step・batch 32・chunk 16。画像の backbone だけ学習率を 1e-5 にする（ACT 論文・LeRobot の既定。画像なしのモデルは今までどおり）
- 推論: 変換設定の画像トピックを購読し、学習時と同じ (3, H, W) float [0, 1] にして渡す
- 画像の拡張（色・位置のランダム化）は最初は入れない。見た目ランダム化での評価で弱ければ検討する

## 結果
2026-10-16、training_eval の実験14（収録 346 本、学習 80k step・96 分）。
- 置き場所ランダム: 59/60（A' は 58/60）。物体位置・置き場所を数値で与えなくても同等に運べた
- 置き場所固定: 39/60（A' は 52/60、p≈0.010）。失敗はすべて持ち上げる前に止まったもので、場所の偏りは小さい
  - 原因の調査（2026-10-17、training_eval の実験14「置き場所固定で下がる原因の調査」）: 失敗は物体の真上で z ≈ 4.4cm と浅いところで閉じて掴み損ね、空のまま運ぶもの。
    同じ物体位置でも置き場所を (0.10, +0.12) や 4.5cm 内側にすると 6/6 で、失敗は置き場所の範囲の外縁（固定位置とその外側）に限られる。
    学習した場面はそのまま 10/10 再現できるが、置き場所を 1〜2cm ずらすと 7/10 に落ちる → 外縁で物体と置き場所の組み合わせを補間できていない（丸暗記に近い）と判断。
    この位置では降下中にグリッパの指が置き場所の円と重なって写る。
    ただし「重なり＝掴んだ後」という見せかけの手がかりを覚えたという仮説は否定した（学習データ 346 本のうち 204 本で掴む前に重なり、閉じる直前でも 50 本。
    それでもデモは通常の高さで閉じている）。重なりが崩れにどう関わるかは特定できていない（training_eval の実験14「指と置き場所の重なりの集計」）。
    評価手順の違い・学習デモの違いは否定。対策の候補は外縁の置き場所のデモ追加、画像の拡張（未実施）
- 見た目ランダム化: 7/30（A' は検出器を挟んで 28/30）。見た目の変化には弱い

色の拡張と seed 1 の評価し直し（2026-10-17、training_eval の実験14「色の拡張と、seed 1 の評価し直し」）:
- 見た目ランダム化の後に置き場所の色が戻らない不具合のため、上の seed 1 は条件が違っていた。評価し直すと拡張なしは置き場所ランダム 58/60・置き場所固定 44/60
- 学習時に色の拡張（明るさ・コントラスト・彩度・色相・シャープネス）を加えると、置き場所ランダム 59/60、置き場所固定 56/60（拡張なし 44/60 から p≈0.006 で改善、A' の 52/60 と有意差なし）、
  見た目ランダム化 15/30（7/30 から改善するが、A' の 28/30 には届かない）
- 見た目ランダム化での差には学習データの違いも含まれる（検出器は見た目ランダム化した画像で学習、画像入力の方策は元の見た目のデモのみ）。
  画像入力の方策を見た目の変化に強くするには、ランダム化したシーンでデモを集め直す必要がある

## 懸念
- 運搬中は物体がグリッパに隠れる。A' では物体位置を固定して対処したが、画像の方策は関節角と画像から直接学ぶので固定はしない
- 学習は画像のデコードと ResNet の分だけ重い。収録データも 1 本あたり数十 MB と大きい
- 物体の位置を数 mm の精度で読めるかがわからない（A' の失敗は「狙いが数 mm ずれる」ものだった）
- 置き場所の範囲の外縁では、物体と置き場所の組み合わせへの汎化が弱い（2026-10-17 の調査）。画像の拡張を入れていないことも効いている可能性がある
